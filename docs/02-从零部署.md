# 02 · 从零部署（换电脑 / 换手机必读）

> 本文是"另一台 Windows 电脑 + 另一台 iPhone"从 0 到能用的完整流程。本机已经装好了，日常不需要重做。
> 顺序不能乱：**驱动 → 通道 → 隧道 → 签名装 WDA → 服务 → 验证**。

---

## 0. 前置清单

| 项 | 要求 |
|---|---|
| 电脑 | Windows 10/11 x64，**一个可用的 USB 口**（别用前置扩展坞） |
| 数据线 | 能传数据的线（很多"充电线"没有数据线芯） |
| iPhone | iOS 16 及以上（iOS 17+ 多一步隧道）；已设锁屏密码 |
| Apple 账号 | 免费 ID 可用（7 天），**强烈建议付费开发者账号**（364 天） |
| 权限 | 装 wintun.dll 需要一次管理员权限 |

## 1. 驱动层：让电脑"看见"iPhone

1. 装 **Apple Devices**（Microsoft Store）或 iTunes —— 它带 Apple Mobile Device Support 和 usbmuxd。
2. 插线 → 手机解锁 → 点"信任" → 输密码。
3. 手机：`设置 → 隐私与安全性 → 开发者模式 → 打开` → 重启 → 确认。

验证（本包自带 go-ios，不需要装 Node）：

```bat
bin\ios.exe list
```

期望：`{"deviceList":[{"deviceID":"YOUR_UDID", ...}]}`

### ⚠️ 头号坑：libusb0 过滤驱动

**症状**：`ios list` 永远返回空，但 iTunes/爱思助手能看到手机。
**原因**：装过 iPhoneMirror / 爱思助手 的"反控/投屏"功能后，它们会给 Apple 复合设备挂一个 `libusb0` **UpperFilter**，把设备从 usbmux 的枚举里摘走。
**注意**：注册表里 UpperFilters 受 PnP 保护，`SetValue` 写不进去（会报拒绝访问）。唯一可靠解法：

```powershell
# 管理员 PowerShell —— 删掉这个设备节点（不是卸驱动）
pnputil /remove-device "USB\VID_05AC&PID_12A8\..."
# 然后【物理拔掉数据线，再插回去】
```

拔插之后 Windows 用干净的过滤器栈重建节点，`ios list` 就通了。
> 原状态备份在你自己的工作目录（例如 `Downloads\driver-backup\`）（`enum-key-backup.json`、`usb-composite-device-original.txt`），需要恢复投屏功能时按备份还原。

## 2. 通道层：go-ios

本包 `bin\ios.exe` 就是 go-ios 1.3.2，`phone.py` 会自动把它放进 PATH。
若要在别处单独用：

```bat
set PATH=%~dp0bin;%PATH%
ios.exe version
ios.exe list
ios.exe info
```

常用：

| 命令 | 用途 |
|---|---|
| `ios list` | 列设备（排障第一步） |
| `ios info` | 硬件/系统信息 |
| `ios apps --list` | 已装 App（bundle id ↔ 中文名，建映射用） |
| `ios screenshot out.png` | 不需要 WDA 的原生截图（截图通道独立于输入通道） |
| `ios forward 8100 8100` | 端口转发 |
| `ios runwda --bundleid ... --testrunnerbundleid ...` | 启动 WDA 测试进程 |
| `ios install app.ipa` | 装 ipa |

## 3. 隧道层：iOS 17+ 必需

```bat
:: 管理员 PowerShell，一次即可
copy bin\wintun.dll C:\Windows\System32\

:: 之后每次开机（或由 service.py 自动做）
set ENABLE_GO_IOS_AGENT=user
set GO_IOS_AGENT_PORT=28100
bin\ios.exe tunnel start
```

**为什么端口是 28100 不是默认 60105**：Windows 的动态端口范围是 49152–65535，Hyper-V/WinNAT 会在开机时预留其中若干段，bind 被拒（报"forbidden by its access permissions"）。选 49152 以下就没事。

**为什么必须 `wintun.dll`**：go-ios 的 userspace 隧道要建一块虚拟网卡走 RSD。缺了它报
`Error loading wintun.dll`，然后 iOS 17+ 上**任何**操作都失败（截图也不行）。

## 4. 输入层：签名并安装 WebDriverAgent

WDA 是一个装在手机上的 App（`WebDriverAgentRunner-Runner.app`），必须签名。

### 4.1 先处理 ipa（关键）

```powershell
# 先运行: python wda/make_ipa.py 生成 wda/WebDriverAgent.ipa（本仓库不含 ipa，见 NOTICE.md）
# 把 Payload/WebDriverAgentRunner-Runner.app/PlugIns/*.xctest 里的 *.dSYM 目录删掉，再重新 zip
```

**不删 dSYM 的后果**：Sideloadly 报 `Failed to process app binary (-69)` 或 `macho sign/edit failed (-40)`，因为 dSYM 是不可签名的调试符号包。
处理完 714 KB（原始 1.1 MB）。

### 4.2 Sideloadly 侧载

1. 下载 Sideloadly（本项目用 v0.72）。
2. **启动方式**：直接双击 `Sideloadly.exe`。（如果是从 Agent/脚本里 `Start-Process` 启动，窗口可能在另一个会话里看不见 —— 那就用 `explorer.exe "<路径>\Sideloadly.exe"` 让它落到当前桌面会话。）
3. `IPA` 那一栏：**拖拽** `wda\WebDriverAgent.ipa` 进去，或点右边的文件夹按钮选。
   > 别在路径框里敲路径按回车——`.ipa` 默认关联可能是爱思助手，会打开它。
4. `Apple ID` 填开发者账号邮箱 → 点 `Start`。
5. 输密码（Sideloadly 在弹窗里问，不是主界面）→ 有 2FA 就填验证码。
6. 看到 `Done.` 即成功。

### 4.3 手机端信任

`设置 → 通用 → VPN与设备管理 → 开发者App → 信任 <你的 Apple ID>`。
（付费账号有时不需要这一步。）

### 4.4 补签嵌套 xctest（如果 WDA 启动即死）

现象：`runwda.log` 里 XCTest `error 103`，或 WDA 起来 2 秒就没了。
原因：Sideloadly 只签了外层 App，`PlugIns/WebDriverAgentRunner.xctest` 没签。

```bat
:: 前提：pip install pymobiledevice3（requirements-full.txt 里有）
phone-harness fix-input
```

它会调 `ios sign app` 用手机上现存的有效 profile 补签（Team ID 会写进 `.state/`），然后再 `ios install`。本机已做过：Team `YOUR_TEAM_ID`，profile 到 **2027-11-09**。

## 5. 服务层：让链路常驻

```bat
up.cmd
```

它会调 `admin.up()`（幂等：已就绪就直接返回），然后**永不退出**，把孩子进程（隧道/转发/WDA runner）拴在一个长寿父进程下。

> 为什么必须常驻：`admin.up()` 拉起的隧道和转发是"子进程"。启动脚本一退出，Windows 就把它们回收——表现就是"刚才还能截图，一秒后 WDA 不见了"。

不喜欢那个黑窗口的话，双击 `start.vbs`（无窗口启动，靠 pythonw）。但**日志就看不见了**，排障时还是用 `up.cmd`。

`up.cmd` 起来后：

```bat
phone.cmd status
:: {"service": true, "wda": true, "app": "com.apple.springboard", ...}
```

### 5.1 关于"自动拉起"的现实

`phone.py` 会尽力自动起服务（`DETACHED_PROCESS`），但**在带 Job Object 的沙箱里（很多 Agent 宿主）分离子进程会被立刻杀掉**——我实测过：子进程连一行日志都来不及写就没了。
所以 phone.py 的降级顺序是：

1. 服务已活 → 直接问服务（最快）
2. 尝试分离启动服务 → 12 秒内探活，进程一死立刻放弃
3. **在当前进程内 `admin.up()`** → 命令一定成功，代价是首条命令多花 ~20 秒，且链路只在这个命令期间有效

**所以：能常驻就常驻（`up.cmd` 留着窗口 / 宿主支持后台任务），别指望沙箱里自动常驻。**

## 7. 换手机时要改的东西

| 东西 | 处理 |
|---|---|
| WDA 签名 | **必须重新签**（profile 绑定 UDID），签名 ipa 含个人证书信息、不能分享 |
| 屏幕尺寸 | 逻辑分辨率变了（Pro Max 是 430×932），任何写死坐标的流程要重测 |
| `.state/` | 可整个删掉，会自动重建 |
| 常驻服务 | 重启一次 `up.cmd` |
