# 06 · 提速全过程：从 15 秒/步 到 1~3 秒/步

## 起点有多慢

最早用投屏 + 反控方案（iPhoneMirror）执行"打开 TestFlight 下载测试包"这种简单任务：

| 环节 | 耗时 | 问题 |
|---|---|---|
| 找 App | 8~15 s | 靠 Spotlight 搜，用坐标点搜索框时落到了 Siri 建议里的抖音 |
| 输入 | +3 s | 用剪贴板粘贴，弹"允许粘贴"要再点一次 |
| 点按钮 | +2~5 s | 按截图算坐标，偶发点错，错了要重来 |
| 截图确认 | +1~3 s | 视频流截帧，画面滞后 |

结论：**不是"慢一点"，是每一次都在赌**。而且换个任务（拼多多查单号、小红书搜视频）整个摸索过程重来一遍。

## 根因分析（5 条）

1. **每步重启进程**：每次调用都拉起一个新的 MCP/工具进程，3~5 s 纯启动。
2. **每步重建会话**：`POST /session` 每次 1~2 s，实际上一个会话可以复用几小时。
3. **每步释放控制权**：`release_control` 会把整个采集会话拆掉，下次重建实测 **10.7 s**。
4. **靠图算坐标**：截图有裁剪/缩放，坐标换算不可靠 → 点错 → 重试 → 更慢。
5. **固定 sleep**：不管界面早就好了，还是硬等 2~3 秒。

## 做了什么

| 改动 | 效果 |
|---|---|
| 换底座：投屏反控 → **WDA** | 从"像素猜"变成"元素树"；`tap-text` 按标签点，不再算坐标 |
| **单进程 CLI**（`phone.py`） | 去掉 3~5 s 的进程启动；一条命令就是一次调用 |
| **会话复用**（`.state/wda_session`） | 省掉每步 1~2 s 建会话 |
| **不再 release** | 省掉 10.7 s 的会话重建 |
| **常驻服务**（`service.py`） | 隧道/WDA/转发不随脚本退出而消失，链路永远热着 |
| **OCR 原生坐标** | 点一次中一次，消掉"点错重试"的隐性成本 |
| **`wait_text` / `wait_stable`** | 用文字/像素稳定性判断，替代固定 sleep，典型省 1~1.5 s/步 |
| **`flow` 批量** | N 步共用一个进程，比逐步调用再快 ~40% |
| **中文直输**（`type`） | 省掉剪贴板 + "允许粘贴"弹窗的两次交互 |

## 实测数字（iPhone 13 / iOS 26.3.1 / USB）

| 动作 | 耗时 |
|---|---|
| `open_app`（已装 App） | 0.12 ~ 1.4 s |
| `ocr`（40~60 个元素） | 0.16 ~ 1.9 s（多数 < 0.7 s） |
| `screenshot`（505 KB 实时帧） | 0.16 ~ 0.43 s |
| `tap_text`（一次命中） | 0.4 ~ 0.7 s |
| `type_text`（3 个汉字） | 0.2 ~ 0.5 s |
| `GET /source`（43 KB XML） | 0.2 ~ 1.5 s |
| 单条命令端到端（含 Python 启动 ~0.6 s） | **1 ~ 3 s** |
| 高德导航全流程（6 步，分步调用） | ~15 s |
| 同上（`flow` 一次跑完） | ~9 ~ 10 s |

## 验收案例：让手机自己导航

任务：打开高德 → 搜"广州塔" → 路线 → 偏好选"不走高速" → 开始导航。

```
open com.autonavi.amap            → 2.1 s
tap 搜索框(132,466) + type 广州塔   → 2.6 s
tap-text 路线                      → 2.4 s
tap-text 偏好 → tap-text 不走高速   → 4.4 s
tap-text 开始导航                   → 3.2 s
```

结果：导航启动，954 km / 18 小时 37 分，避开高速（对照：默认推荐路线 855 km，走高速）。
**全程 6 步 15 秒，没有一次点错、没有一次重试。**

## 还能更快吗

- 已到"每步 1~3 秒"这个量级，剩余成本主要是 **Python 启动（~0.6 s）+ 一次 HTTP 往返 + iOS 动画时间**。
- 真正还能省的是"步数"：能合并的步骤用 `flow`；能在一次 `ocr` 里判完的状态不要拆两次查。
- 不建议再压 tap 的按住时长（`WDA_TAP_HOLD_MS`，默认 80 ms）：更短会偶发丢点，**漏一次点的代价远大于省下的 40 ms**。
